# crewbot v7 feature audit and design coverage

Audited source: `/home/xdd/dev/work/crewbot`, commit `1145fc828e617152cb185ef519f90cb56db6f3b9`, 2026-10-08. Paths in the table are relative to that repository. The renderer is `src`, mounted by `src/main.tsx`. `/pair` is a distinct authentication route; chat, team map and routines are store-selected app views rather than separate URL pages. Preview/testing entry points are development tools, not additional shipped screens. `apps/docs` is the separate documentation site, linked through Help. No crewbot source was changed, no server was started and no live app data was used. This is a source audit and visual design deliverable, not runtime verification.

## Information architecture

Home is a personal conversation with Maus. Crew presents Atlas · Engineering, Nova · Marketing and Sage · Product, with specialist bots underneath. Projects presents the central group or project-attached direct conversation. Staffing, context, goal progress, tools and computer views are secondary chips, popovers or sheets. Global search, attention, workspace switching and avatar menu remain reachable everywhere. Automations, Apps & tools, Settings and Help are secondary destinations.

Existing data keeps its meaning. Bot thread folders remain folders. A project groups conversations and references existing room, bot and workspace identities; it does not convert every old folder into a staffed team. Existing custom teams, Chiefs, extra managed scopes, DMs, archived records, engine assignments and conversation IDs survive. New lead names and the Maus landing are an approved presentation direction, not a mandate to replace existing profiles or grant new authority. Task defaults and live task execution places remain separate.

The canvas extends edge to edge. Navigation, headings, lists and calendar grid sit directly on the ASCII sky. Conversation, composer, compact content cards and temporary review sheets use translucent glass. No outer application card or persistent settings wall. Every design is Light as requested; the existing eight appearance choices remain accessible.

## Preservation rules and capability boundaries

- Linux is the current supported delivery platform. Existing macOS speech recognition, native Android/iOS clients, Windows/macOS adapters and chrome remain retained, with acceptance deferred. Linux call/dictation controls show the actual unavailable reason. TTS playback is independently gated. Preserve current Wayland/display-session safety gates; these images establish no distro or session compatibility evidence.
- Remote client settings and profiles expose their implemented subset. Hosted human admission, fleet administration, organization enrollment, cloud backups and shared-computer grants each retain separate entitlement/trust checks. Disabled or omitted actions have a contextual explanation, not fake capability.
- Workspace secrets stay write-only. OAuth account connection, bot app allowance, selected account grants, MCP registry, per-bot server selection and Claude user-MCP are independent controls. Key values never appear in chat or prefilled saved fields.
- Destructive operations keep explicit target, busy/eligibility checks, confirmation, pending/error/recovery and cancel paths. Backup restore preserves literal REPLACE, preview and boot recovery; DELETE applies to company backup deletion. Conversation deletes, archives, folder deletion and environment forgetting have different effects.
- Search lands on the exact thread, message and active branch. Drafts, reply references, versions, queue identity, execution/result thread distinction, detached automation runs and attachment authorization survive the visual change.
- Goal receipts have status and turn limits but no existing pause/resume editor. Routine definitions do have pause/resume and run cancellation. Transcript export offers Markdown, not public sharing. The current Ctrl+K palette switches/searches; a general command registry would be new work.
- Existing skin selection is not a binary theme toggle. No font-size/theme editor, persistent notification archive, custom usage date-range UI, live interactive in-app terminal or general file explorer was found. File handling is attachments, Markdown downloads, code snippets, working-folder selectors and memory-topic editing. Terminal functionality is tool command/output evidence, external-terminal install/auth handoffs and explicit shared-terminal permission.

## Gaps and redesign acceptance

1. Current thread folders are not staffed projects. A real Projects product needs explicit group/workspace membership semantics; preserve existing folders, links and results destinations while deciding that model.

6. Map owns computer/team assignment, persistent arrangement and handoff navigation. A roster replacement needs equivalent homes or must retain map access.
7. Search empty/failure states, archived crew recovery, unread/waiting signals, remote-client gates and onboarding anchors are likely omissions in a purely screen-based redesign plan.
