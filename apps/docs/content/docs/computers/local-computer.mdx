Linux is the only supported platform during active development. Local control is off by default. On Ubuntu 24.04 GNOME/Xorg, enable it explicitly and assign each bot separately; every action still uses the approval flow. The Electron main process owns the bundled CUA driver lifecycle. Linux installed acceptance remains pending; see the [platform support policy](https://github.com/xddinside/crewbot/blob/main/docs/platform-support.md).

## Parked macOS source

The native permission implementation remains in source. macOS support and its local-control acceptance are parked, so this is not a current setup path.

## Ubuntu 24.04 GNOME

On GNOME/Xorg, open Settings, choose **Enable local control (Beta)**, wait for **Ready**, then choose **This computer** for the bot. Control requires explicit opt-in and every action still follows approvals. On GNOME/Wayland, local control stays disabled and legacy opt-ins are cleared. Screen preview uses the GNOME portal and does not grant control. The [Ubuntu desktop guide](https://github.com/xddinside/crewbot/blob/main/docs/linux-desktop.md) describes both session boundaries. Android USB device control through Phone Harness is a separate Linux feature.

## Safety model

- Enabling local control globally does not assign it to a bot.
- Choose **This computer** for each bot that should receive the capability.
- Risky actions still surface through the approval flow.
- Missing permissions, unexpected binaries, unsupported desktop sessions, and failed health checks fail closed.
