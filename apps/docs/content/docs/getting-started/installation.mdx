## Linux release status

Linux is the only supported platform during active development. Arch Linux is the daily development target; Ubuntu 24.04 x86_64 is the package and CI reference. Linux installed continuity and recovery acceptance is still pending, so there is no supported public CrewBot Linux release to download yet.

After acceptance and publication, the manual [Ubuntu package workflow](https://github.com/xddinside/crewbot/blob/main/.github/workflows/package-linux.yml) will provide the `crewbot-ubuntu-<version>-x64` artifact with:

- `crewbot-<version>-amd64.deb`
- `crewbot-<version>-x86_64.AppImage`
- `crewbot-amd64.deb` and `crewbot.AppImage` stable names
- `SHA256SUMS-ubuntu-x64.txt`, with four hash rows for the DEB and AppImage files
- `latest-linux.yml`, with versioned package names, SHA-512 hashes, and file sizes

The Linux CI gate also retains an ARM64 Cloudflare connector installer smoke. That checks connector staging only; it does not establish ARM64 desktop support. See the [Linux platform support policy](https://github.com/xddinside/crewbot/blob/main/docs/platform-support.md) for acceptance status and coverage limits.

## Build from source

Use Linux x86_64 with Node.js 24 or newer, pnpm 10.33.0, and at least one authenticated agent CLI. The repository's [contribution guide](../contributing/index.mdx) lists the required checks.

```bash
git clone https://github.com/xddinside/crewbot.git
cd crewbot
corepack enable
pnpm install --frozen-lockfile
```

Run the harness, web UI, and Electron shell in separate terminals. `pnpm dev` uses Portless for the web UI.

```bash
pnpm dev:server
pnpm dev
pnpm dev:desktop
```

For package build and Ubuntu desktop behavior, see the [Ubuntu desktop guide](https://github.com/xddinside/crewbot/blob/main/docs/linux-desktop.md).

## Parked native platforms

Native Android, iOS, macOS, and Windows support is parked. Their source and historical build instructions remain in the repository, but their builds and acceptance do not gate Linux delivery. Old OpenMausBot `.dmg` and `.exe` releases are upstream history, not CrewBot downloads. Android is reconsidered after dependable Linux daily use; other platforms require public release, demonstrated demand, and an explicit decision to resume support.

## Agent CLI setup

OpenMausBot needs at least one agent engine installed and signed in. Claude and Codex are common starting points.

1. Install the CLI from its official provider.
2. Run it once in a terminal and complete sign-in.
3. Restart OpenMausBot.
4. Open the model picker. Available engines appear normally; unavailable engines explain what is missing.

See [Agent engines](../providers/index.mdx) for the complete list and explicit path overrides.

## Where data lives

Linux application data and configuration locations are described in the [Ubuntu desktop guide](https://github.com/xddinside/crewbot/blob/main/docs/linux-desktop.md). Preserve existing OpenMausBot data when upgrading or migrating; do not delete it as part of installation.
