## Current release status

Linux is the only supported platform during active development, but installed continuity and recovery acceptance is still pending. There is no supported public CrewBot Linux release to update yet. Do not use old OpenMausBot or unrelated repository assets as CrewBot updates.

After a CrewBot release is published, the manual Linux package workflow provides the `crewbot-ubuntu-<version>-x64` artifact. It contains six files:

- `crewbot-<version>-amd64.deb`
- `crewbot-<version>-x86_64.AppImage`
- `crewbot-amd64.deb`
- `crewbot.AppImage`
- `SHA256SUMS-ubuntu-x64.txt`, with four rows for the DEB and AppImage files
- `latest-linux.yml`, with versioned package names, SHA-512 hashes, and file sizes

The AppImage can update itself in place and keeps the path you launched. A DEB update downloads and verifies the package, then gives you an `apt-get` command to run; the app does not install system packages or ask for your administrator password. See the [Linux package workflow](https://github.com/xddinside/crewbot/blob/main/.github/workflows/package-linux.yml) and [platform support policy](https://github.com/xddinside/crewbot/blob/main/docs/platform-support.md).

## The download keeps spinning

After a release is published, leave the app open for one complete update attempt, then quit and reopen it. If the same release remains stuck, download the matching official Linux artifact from the [CrewBot releases page](https://github.com/xddinside/crewbot/releases) and verify it against `SHA256SUMS-ubuntu-x64.txt` before installing it over the existing copy.

For a DEB, install the downloaded versioned file with APT so its dependencies are resolved:

```bash
sudo apt-get install -y ./crewbot-<version>-amd64.deb
```

For an AppImage, replace the file at the path you launch. Keep the existing application data; replacing the package does not require deleting it.

## Restart to update does nothing

Quit the app completely and launch it again. If the version did not change, use the official release's matching Linux package as described above. The installed version runs the updater, not the version being downloaded. Keep your application data when recovering from a stuck update.

## Report an update failure

Open **App settings → General → Diagnostics → Export Diagnostics…**. Include your operating system, the installed version, the target version, and whether the failure happened during download or restart. Review the exported file before sharing it privately with support.

## Verify the installed version

Open **App settings** and check the displayed version. A commit merged to `main` is not part of the desktop app until a release workflow publishes it.

<Callout type="warn" title="Use official Linux artifacts">
  Install only files from the CrewBot releases page. Verify the SHA-256 manifest before installing a downloaded package. Do not install forwarded files or assets from another repository.
</Callout>
